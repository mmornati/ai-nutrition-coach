OpenPlate v1
Architecture Spine

A calm, local-first nutrition coach. One responsive Flutter app over a pure-Dart hexagon; the local encrypted store is the source of truth; AI is a swappable rung, never the product.

Flutter 3.47.0Dart ^3.13 drift 2.34.3 · ChaCha20-Poly1305Riverpod 3.4.2 no account · telemetry off

01 · The shape

Hexagonal ports-and-adapters with one shared pure-Dart domain core. Domain rules, entities, and the coach taxonomy live in domain_core and know nothing of Flutter, SQLite, or HTTP. Every outside concern — store, OFF/USDA, AI, sync, export, barcode, camera — is an adapter bound to a core port. The no-AI core is a complete product.

02 · Invariants

Nine rules bind every builder. Two units one level down that each obey them cannot build incompatibly.

AD-1 · Shared pure-Dart core

Binds: all. Domain entities, use-cases, coach model in domain_core — no Flutter, SQLite, or HTTP imports. UI never imports drift/dio/mobile_scanner directly: only through ports.

AD-2 · One responsive Flutter codebase

Binds: FR-11/12, UJ-1..5. iOS, Android, and the self-host web build are one app that responds to form factor. Desktop is v2 — a new target, not a new codebase.

AD-3 · Store is the single source of truth

Binds: FR-5/9/10, SM-3. Every mutation flows through a use-case that commits to the store before the UI reflects it. Riverpod providers are derived views, never a second source. Coach answers logged the same way.

AD-4 · One FoodCatalog port

Binds: FR-1/2/3. Photo, barcode, and manual paths call the same port with a local cache in front of OFF+USDA. One lookup path, one cache, one data shape.

AD-5 · AI is a swappable rung

Binds: FR-6/7/8. One AiRung port; exactly one active implementation chosen by config: no-op (the complete no-AI core), hosted-quota, byok, local (v2 seam). The core never branches on which rung is on.

AD-6 · Offline-first; sync never loses data

Binds: FR-9/10, UJ-5. Writes never wait on network. A durable outbox drains to user-controlled infrastructure only; retries silently; ·synced only after remote ack. No third-party sync.

AD-7 · Coach copy in a key store

Binds: FR-4 NFR, FR-15, FR-15 QA gate. Every coach string is a keyed, localized template. No anonymous string interpolation in widgets; No-Dark-Patterns is a CI checklist.

AD-8 · Honest at-rest encryption

Binds: FR-9/7. Mobile: ChaCha20-Poly1305 via sqlite3mc build-hook, key in Keychain/Keystore. Web: same schema on sqlite3.wasm with a passphrase-derived key in memory — weaker, and documented as such. BYOK keys never leave the device.

AD-9 · Export is a read-only port

Binds: FR-9 consequence, Settings · Your data. CSV/JSON streams from the source of truth, offline, no account required — lost my history is impossible by construction.

05 · Self-host envelope

One command, one image, static web client. Reproducible multi-stage build; the web app is the same apps/client codebase.

FROM ghcr.io/cirruslabs/flutter:stable AS build
WORKDIR /src
RUN flutter build web --release            # default JS + CanvasKit

FROM nginx:alpine
COPY --from=build /src/build/web /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf   # try_files $uri /index.html

06 · What is deliberately deferred

  • Cross-device sync mechanism — seam reserved (AD-6); concrete path decided at build.
  • Free-model quota provider — Cloudflare vs Gemini is an adapter selection behind AD-5.
  • Local model rung (FR-8) — v2, seam already drawn.
  • Managed-oversight profiles (FR-14) — v2, pending legal validation (PRD OQ4).
  • Desktop clients, OFF write-back, week coach summary — v2 / v1.5, no architecture change needed.
