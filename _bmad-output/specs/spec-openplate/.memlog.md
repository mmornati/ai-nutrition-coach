- (capability) CAP-1 Photo logging: user logs a Plate Log by photographing the plate; system recognizes foods and resolves them to Database Foods with honest quantity ranges. Success: a single well-lit plate photo returns recognized Food Entries in <=3s on a midrange device; ambiguous photos fall back to closest-matches/manual without failing the log; quantities shown as honest ranges (e.g ~2 fists), never false-exact kcal. (FR-1, UJ-1)
- (capability) CAP-2 Barcode logging: user logs a Database Food by scanning a barcode via OFF lookup (no API key for reads). Success: known barcode resolves to a Database Food in <=2s; unknown barcode reaches a graceful not-found state with a manual-add path. (FR-2, UJ-2)
- (capability) CAP-3 Manual/voice logging: user logs a Plate Log by typing or voice-inputting a food name (speech-to-text transcription only, never voice-print). Success: partial text returns ranked Database Food matches with quantity presets; manual logging works with the AI tier fully off and offline. (FR-3, UJ-5)
- (capability) CAP-4 Coach Note generation: after a Plate Log resolves, the system produces a Coach Note containing one Coach Question on balance/composition in plain non-judgmental language. Success: every resolved Plate Log can produce a Coach Note (AI on: richer; AI off: template on resolved food groups); notes never contain calorie-shaming, streak-pressure, or restriction framing. (FR-4, UJ-1)
- (capability) CAP-5 Coach Question interaction: user can answer, dismiss, or request depth on a Coach Question. Success: answering produces a bounded follow-up Coach Note; dismissing records no score/streak/guilt; interaction logged locally only. (FR-5, UJ-1, UJ-4)
- (capability) CAP-6 AI tier ladder: user can opt into AI tutoring through a free-model quota (default) or bring their own OpenAI-compatible key; the no-AI core stays complete and undegraded. Success: quota exhaustion downgrades to the no-AI core with a plain-language 3-way choice (wait / BYOK / keep logging without AI); BYOK key stored encrypted on-device and never transmitted to any server; removing the key returns cleanly to the previous rung. (FR-6, FR-7, UJ-3, UJ-4)
- (capability) CAP-7 Local-first encrypted data: system stores all Plate Logs and Coach Note history in an encrypted local store with no server-side mirror and no account requirement; export available in portable format. Success: full feature set works with network revoked; at-rest data encrypted AES-256 (platform-aware); CSV/JSON export available offline. (FR-9, UJ-1, UJ-5)

- (capability) CAP-9 Self-host & OSS: a non-expert can install/run OpenPlate on their own server with a single documented command; responsive web client served; repo public at launch with permissive FOSS license and documented No-Dark-Patterns Standard. Success: Docker host -> one-command install brings web client up against the local store in <=5min (CI smoke-tested); LICENSE + CONTRIBUTING + published No-Dark-Patterns Standard exist at tag time; telemetry off by default in all shipped builds. (FR-11, FR-12, UJ-3)
- (capability) CAP-10 Adults-only & no-dark-patterns enforcement: v1 offers no child accounts, collects no data attributable to known children, uses no biometric identification, and no surface uses countdown pressure, fabricated urgency, streak-guilt, reward-bait, or age-lying nudges. Success: no signup flow can produce an under-13 profile; no face/voice-print recognition anywhere in the pipeline; No-Dark-Patterns Standard enforced as a QA checklist gate in CI with a named reviewer owning the pass. (FR-13, FR-15)
- (constraint) AD-1 Shared pure-Dart domain core (package domain_core) with no Flutter/SQLite/HTTP imports; apps/client and packages/integrations depend on it, it depends on nothing; UI never imports drift/dio/mobile_scanner directly, only through ports.
- (constraint) AD-2 One responsive Flutter codebase for all three targets (iOS/Android/web); flutter build web serves the self-host client; desktop deferred, not a separate codebase.
- (constraint) AD-4 One FoodCatalog port in front of OFF + USDA with a local cache adapter; all three entry paths (photo, barcode, manual/voice) call the same port.
- (constraint) AD-5 AI is a swappable tier behind one AiRung port with exactly one active implementation chosen by config: no-op (complete no-AI core), hosted-quota, byok, local (v2 seam); core never branches on which rung is active, only on whether a port call succeeded.
- (constraint) AD-6 Offline-first writes; sync is an adapter draining a durable outbox queue to user-controlled infrastructure only; retries silently on reconnection; a log is synced only after durable remote acknowledgment; no third-party sync; status chips derive from queue state.
- (constraint) AD-7 Every user-facing coach string (whispers, notes, quota notices) is a keyed, localized template in a key store; no string interpolation in widgets; No-Dark-Patterns Standard is a QA checklist gate in CI/review owned by a named reviewer.
- (constraint) AD-8 At-rest encryption is honest and platform-aware: mobile AES-256 via sqlite3mc build hook with 32-byte DB key from flutter_secure_storage (Keychain/Keystore); web runs the same drift schema on sqlite3.wasm with a passphrase-derived PBKDF2 key in memory for the session only, documented as weaker, never asserted equivalent; BYOK key always via flutter_secure_storage, never leaves the device.
- (constraint) AD-9 Export is a read-only Exporter port streaming the store's Plate Logs to CSV/JSON on demand; available offline; never requires an account.
- (constraint) AD-3 Local encrypted store is the single source of truth: every domain mutation flows through a core use-case that commits before UI reflects it; Riverpod UI state is derived, never a second source; sync reads from the store and never writes outside it.
- (constraint) Stack web-verified current Aug 13 2026: Dart ^3.13.0, Flutter 3.47.0, flutter_riverpod 3.4.2 (codegen), drift/drift_dev 2.34.3/2.34.x, sqlite3 3.5.x (sqlite3mc build hook), flutter_secure_storage 11.0.0, mobile_scanner 7.4.0, image_picker 1.2.3, dio 5.11.0, melos 8.2.2, patrol/patrol_cli 4.8.0/4.6.1; test/flutter_test/integration_test SDK-bundled.
