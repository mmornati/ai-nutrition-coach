## Phase 4: Storage (encrypted store, key, lifecycle)

Store design to reproduce (proven in the Flutter web build)
- [x] Encrypted at rest; a plaintext/different-key open must fail; a wrong passphrase can never open the store and nothing is written. Flutter used sqlite3mc ChaCha20-Poly1305 (cipher pinned explicitly with `PRAGMA cipher`, key via `PRAGMA hexkey`, verified by forcing a page decrypt before use). `INT/store/sqlite_key_attach.dart`, `INT/store/web_database_backend.dart`, `ADR/ADR-0002-web-encrypted-store.md`
- [x] Key = PBKDF2-HMAC-SHA256, 600,000 iterations, 32-byte output, random 16-byte per-store salt, via `crypto.subtle.deriveBits` (async, off the UI loop); refuse a stored header below the 600k floor. `INT/store/web_kdf.dart`, `INT/store/web_crypto_kdf.dart`, `packages/integrations/test/web_kdf_test.dart`
- [x] Passphrase input: Unicode NFC-normalised then UTF-8 bytes (so the same visible passphrase works on any keyboard); the header records `"pw":"nfc-utf8"` and a different value is refused. `INT/store/web_store_meta.dart`
- [x] Non-secret header `{"v":1,"kdf":"pbkdf2-hmac-sha256","iter":600000,"pw":"nfc-utf8","salt":"<base64url>"}` in localStorage (key `anc.pwa.store.meta`; renamed for the new app so it can never collide with the old Flutter web build, which used `ai_nutrition_coach.web.store.meta`) PLUS a copy in a separate IndexedDB database (`anc_pwa_header_v1`, was `ai_nutrition_coach_header_v1`) so losing localStorage alone does not orphan the store; malformed/unknown-version/short-salt/downgraded headers are refused. `INT/store/web_store_meta.dart`, `INT/store/web_header_copy.dart`, `INT/store/web_local_storage.dart`
- [x] localStorage read/write must THROW when the browser refuses storage (a swallowed error would look like "no store yet" and lead to wiping real data). `INT/store/web_local_storage.dart`
- [x] Controller state machine: `checking -> needsPassphraseCreation | locked | needsReset | unavailable` (new in the PWA: a storage READ that fails is `unavailable` and offers retry, never `needsReset`/erase), `unlocked`, `erasing`; header is written only AFTER the keyed database opened; creating over an orphaned database erases it first; a returning user whose data is missing gets `needsReset` (never a fresh empty store). `INT/store/web_store_controller.dart`, `packages/integrations/test/web_store_controller_test.dart`
- [x] Key held in memory only while unlocked, never written to any browser storage; lock zeroes the key buffer, closes the database, and flips status BEFORE awaiting the close; docs never claim forensic erasure from RAM. `INT/store/web_session_key.dart`
- [x] Passphrase strength floor for a NEW passphrase: >=10 characters and >=4 distinct characters; the two fields must match. `INT/store/web_store_controller.dart`, `APP/widgets/create_passphrase_body.dart`
- [x] Unlock throttling: none for the first 2 failures, then 1 s, 2 s, 4 s, capped at 30 s; it is UX friction only, lives in tab memory, and must NOT be described as a security control. `INT/store/web_store_controller.dart`, `docs/your-data.md`
- [x] Outcomes handled distinctly: wrong passphrase, throttled, weak passphrase, storage unavailable (private mode / blocked IndexedDB / missing wasm; never reported as a wrong passphrase), in use in another tab, data written by a newer version (locked, "reload to update", not counted as wrong passphrase), data missing. `INT/store/web_store_controller.dart`, `INT/store/web_database_backend.dart`
- [x] Single tab at a time via the Web Locks API (`navigator.locks.request(..., {ifAvailable: true})`, lock name `anc-pwa-store` (was `ai-nutrition-coach-store`; renamed for the new app), held until lock/close; released by the browser if the tab dies); a browser without Web Locks degrades to "not enforced", not a lock-out. `INT/store/web_locks.dart`, `INT/store/web_store_lock.dart`
- [x] Auto-lock: idle timeout default 15 min (choices 5/15/30/60, persisted in localStorage `anc.pwa.lock.idleMinutes`, was `ai_nutrition_coach.web.lock.idleMinutes`), lock after the page has been hidden 5 min, manual Lock; pointer/key activity resets the idle timer. `INT/store/web_store_controller.dart`, `APP/widgets/unlock_gate.dart`
- [x] Every unlocked->locked transition discards all decrypted UI/query state (the app restarts its state scope); every locked->unlocked transition rebuilds state from the freshly opened database (settings and BYOK key live inside it). `APP/widgets/unlock_gate.dart`
- [x] Erase all local data: closes the DB, deletes every persisted byte (database pages, journals, IndexedDB header copy, localStorage header), returns to first run; also the recovery path for "forgot passphrase" and "store can't be found"; steps are independent and best-effort and the result names failures. `INT/store/web_store_controller.dart`, `INT/store/local_data_eraser_stub.dart`, `DOM/ports/local_data_eraser.dart`, `packages/integrations/test/local_data_eraser_test.dart`
- [x] Secure context required: `crypto.subtle` is undefined on plain HTTP, so the store reports "unavailable" with an HTTPS explanation (never "wrong passphrase"). `INT/store/web_crypto_kdf.dart`, `docs/self-host.md`
- [x] Ask the browser for durable storage once after create/unlock (`navigator.storage.persist()`) and show one plain line with the answer ("protected from automatic clean-up" or "the browser may clear this data..."); never nag. `INT/pwa/pwa_platform.dart`, `docs/pwa.md` ("Storage and persistence")
- [x] The wasm cipher binary is pinned and SHA-256 verified before it can enter a build, served with a versioned filename and `immutable` caching, never committed; any re-pin is a conscious change. `scripts/fetch_web_sqlite.sh`, `INT/store/web_database_backend.dart`, `packages/integrations/test/web_wasm_pin_test.dart`
- [x] NOTE (design risk): the Flutter wasm is built for the Dart `sqlite3` bindings and cannot be reused. The plan now targets a sqlite3mc JS/WASM build (ChaCha20-Poly1305) in a dedicated Web Worker on the OPFS `opfs-sahpool` VFS, which differs from the proven ADR-0002 (IndexedDB VFS on the main thread; OPFS and a worker were rejected there). The Phase 0 spike must confirm it on iOS Safari and record the outcome in a follow-up ADR; plan B is `@sqlite.org/sqlite-wasm` + `opfs-sahpool` with app-level AES-GCM per row. `ADR/ADR-0002-web-encrypted-store.md`, `docs/pwa-refactor-plan.md`
- [x] Dev-only unencrypted in-memory store behind an explicit dev flag, honoured only in a dev build, with a visible "DEV, not encrypted" banner; a production bundle must not contain the path (test it). `INT/config/build_config.dart`, `INT/store/create_encrypted_store_web.dart`, `APP/main.dart`, `.env.example`

Schema and queries (new schema, version 1; no migration chain)
- [x] Tables: `plate_log`, `food_entry` (denormalised food + quantity low/high + `food_group`), `coach_note`, `coach_interaction` (append-only), `coach_dismissal` (key primary), `kv`; no DB-level foreign keys (enforced in use-cases); indexes on plate `logged_at`, entry `plate_id`, note `plate_id`. `INT/store/app_database.dart`, `INT/store/tables/*.dart`
- [x] Timestamps stored as UTC ISO-8601 with millisecond precision; rendered local by the UI. `INT/store/app_database.dart`, `INT/store/plate_queries.dart`
- [x] Ranged queries are filtered in the store (day/week/export), never by loading the whole history; `watchRange` re-emits on change; locked store emits nothing and returns typed failures. `INT/store/plate_queries.dart`, `INT/store/wasm_encrypted_store.dart`
- [x] A refused open of data from a NEWER schema (never run old code over a newer layout); migrations, when they exist, must be safely re-runnable. `INT/store/app_database.dart`
- [x] Corrupt rows (bad timestamp, invalid quantity) are skipped with a content-free log (row id + fixed reason, never values) and counted. `INT/store/corrupt_row_log.dart`, `packages/integrations/test/corrupt_row_log_test.dart`
- [x] Store errors map to typed failures with no cause text (SQLite messages can embed SQL, paths or key material); a lost key / cipher problem is distinct from a generic storage error. `INT/store/store_error_mapper.dart`, `packages/integrations/test/store_error_mapping_test.dart`
- [x] Store contract suite runs against every implementation (real encrypted store, in-memory fake): record, read range, watch, delete cascade, failures. `packages/integrations/test/_support/store_contract.dart`, `packages/integrations/test/store_contract_test.dart`, `apps/client/test/state/fake_store_contract_test.dart`
- [x] Small encrypted key/value table; reads while locked answer "nothing known", writes while locked throw `KeyValueStoreLocked` (a lock must never look like "value gone"). Keys: `ai.settings`, `ai.byokKey`, `export.lastAtUtc`, `export.reminderDismissedAtUtc`, `privacy.aboutAckAtUtc`, `privacy.offLookup`. `INT/store/key_value_store.dart`, `packages/integrations/test/key_value_store_test.dart`
- [x] Failed-open stores: when the database cannot be opened the UI gets typed calm failures and nothing is written. `INT/store/failed_store.dart`
- [x] Serialise read-modify-write sequences over async storage with a FIFO mutex. `INT/util/async_mutex.dart`

Export
- [x] CSV: fixed header order, columns only ever appended (`food_group` last), UTF-8, header-only file for an empty list, one row per food entry. `INT/export/csv_exporter.dart`, `packages/integrations/test/csv_exporter_test.dart`

## Appendix A: Exact CSP and headers currently served

From `infra/nginx/templates/ai-nutrition-coach-headers.inc.template` (included in EVERY location). `${AI_NUTRITION_COACH_CONNECT_SRC_EXTRA}` is empty by default.

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; media-src 'self' blob:; worker-src 'self' blob:; connect-src 'self' https://world.openfoodfacts.org ${AI_NUTRITION_COACH_CONNECT_SRC_EXTRA}; manifest-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
X-Frame-Options: DENY
Permissions-Policy: camera=(self), microphone=(), geolocation=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
```

Notes for the port:
- `'wasm-unsafe-eval'` is needed for the SQLite/cipher wasm and zxing-wasm (and was also needed for CanvasKit). Keep.
- **Phase 8 result:** `'unsafe-inline'` is gone from `style-src`. React's `style={}` props are applied through the CSSOM (`element.style`), which `style-src` does not govern (only `style=""` attributes parsed from markup and `<style>` elements are); Tailwind's CSS is a file. Proven in WebKit and Chromium (the e2e `page` fixture and the browser smoke fail on any "Refused to ..." console message other than a deliberate `connect-src` one) and by `scripts/smoke_self_host.sh`. `vite dev` still adds `'unsafe-inline'` for HMR; the release never has it. If a future dependency injects a `<style>` element this becomes a red build, which is the point.
- **Phase 8 result:** `base-uri 'none'` works (the app sets no `<base>`).
- The build's `<meta>` CSP carries only `script-src`, `worker-src`, `object-src`, `base-uri`, `form-action` (no `default-src`, no `connect-src`).
- `connect-src` must never become `https:`; the smoke test asserts that.
- `worker-src 'self' blob:` covers the service worker; a SQLite worker (if the OPFS route is chosen) also falls under it.
- Traefik/Caddy add only `Strict-Transport-Security`; the app's own headers pass through untouched.
